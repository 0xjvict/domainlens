## Codebase Patterns
- Schema scanners follow a dispatcher pattern: `schema.ts` routes to `schemaPostgres.ts` or `schemaMysql.ts` based on `db_type`
- Database type is configured in `config.json` (`db_type`) or inferred from URL protocol via `new URL(dbUrl).protocol`
- MySQL ENUM types are inline in `COLUMN_TYPE`, not separate system catalog entries — parse via regex
- Tests use vitest with `describe.runIf(process.env.RUN_INTEGRATION_TESTS)` to skip integration tests by default
- mysql2/promise uses `connection.query()` returning `[rows, fields]`, different from pg's `client.query()` returning `{ rows }`
